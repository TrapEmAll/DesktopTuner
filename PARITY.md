# StartAllBack parity tracker

This tracker uses StartAllBack's public product description as the baseline. Its official page currently advertises a classic-style Start menu, a redesigned taskbar, File Explorer and Control Panel styling, context-menu changes, and cross-app visual consistency. The detailed list below is an implementation target, not a claim that each item has equal internals or exact visual fidelity.

The companion Explorer maps mouse side buttons to Back and Forward in the active tab's folder history.

Replacement-mode auto-hide now also registers each edge-docked taskbar with Windows through the monitor-specific AppBar API. The registration is released when disabled or when the appbar closes; if Windows reports an existing owner on that monitor edge, Desktop Tuner retains its local auto-hide behavior. Live auto-hide and collision behavior still need Windows 11 desktop validation.

Windows [Shell Launcher](https://learn.microsoft.com/en-us/windows/configuration/shell-launcher/) can replace `Explorer.exe` as the logon shell on Enterprise, Education, and IoT Enterprise editions; it does not replace taskbar features individually and also removes Explorer's desktop shell. Windows 11 Pro additionally supports Microsoft's per-user [Custom User Interface policy](https://learn.microsoft.com/en-us/windows/client-management/mdm/policy-csp-admx-winlogon#customshell), which starts an alternate interface instead of Explorer; Desktop Tuner detects when that policy points to its executable and enters `--shell-host` mode. Taskbar settings can set and restore this per-user policy on supported editions. A supervisor retries a failed shell process once and returns to Explorer if the retry fails or the shell exits normally; sign-in/recovery behavior remains unvalidated on a live desktop. The `--shell-overlay` remains available on Home, Pro, and managed editions; it hosts its desktop, Start, and taskbars on every display, covers Explorer's main taskbar controls, and retains Explorer in the background with the native notification area exposed on supported layouts. The per-user shell setting is opt-in. Native desktop icon behavior, multi-monitor icon layout, full shell namespace, native notification-area integration in `--shell-host` mode, recovery/sign-in validation, and managed-edition testing remain. The current Windows App SDK and Win32 documentation do not provide public APIs for replacing native taskbar internals or arbitrary built-in Start visuals. Reaching behavioral parity in those areas will require compatibility-tested shell integration and a Windows-build test matrix; registry toggles alone do not meet the objective.
