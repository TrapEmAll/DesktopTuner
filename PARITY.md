# StartAllBack parity tracker

This tracker uses StartAllBack's public product description as the baseline. Its official page currently advertises a classic-style Start menu, a redesigned taskbar, File Explorer and Control Panel styling, context-menu changes, and cross-app visual consistency. The detailed list below is an implementation target, not a claim that each item has equal internals or exact visual fidelity.

| Area | StartAllBack capability | Desktop Tuner status |
|---|---|---|
| Start | Customizable system-place menu | Partial: Settings can hide and reorder shortcuts such as Documents, This PC, Control Panel, Network, Recent items, and Run; nested folder flyouts remain available for visible Documents, Downloads, Music, Pictures, and Videos entries |
| Start | Search and launch apps | Partial: companion launcher loads Start-menu shortcuts and `shell:AppsFolder` apps on a background STA thread to keep the launcher responsive, ranks exact, prefix, word-boundary, and substring matches across app and folder names, then permits a bounded one- or two-edit fallback on longer query terms; groups the all-apps list with alphabet markers and a `#` section for numeric or symbol prefixes, and displays shell-extracted icons where available; context menus can open the source folder for existing desktop shortcuts and executables or launch them through Windows UAC, while packaged Windows apps are not offered elevation; unmatched Enter searches hand off through Windows' `search:` protocol, and explicit Windows Search and web search actions are available; `Ctrl+Alt+Space` and optional Windows-key replacement with Win+key passthrough work; authentic Windows Start integration remains |
| Start | Classic menu styles, system-place shortcuts, and dropdown navigation | Partial: Modern, Classic, Compact, Windows 7-inspired two-column, Windows 8-inspired pinned-tile grid, and Windows 10-inspired two-column app-list/tile layouts with persistent pinned-app favorites with user-created, renameable tile groups in the Windows 8/10-inspired layouts, configurable Small/Medium/Wide/Large tile sizes, and drag-to-group; an optional placement preference centers the Start menu along the selected taskbar edge; pins can be added by dragging from app search/all-apps or the Classic folder tree, dropping `.lnk` shortcuts, `.exe` files, or folders from Explorer or the desktop, or using context menus; folder pins launch their folder in File Explorer; app pins can be reordered by drag-and-drop or context menu; the launcher surfaces a configurable zero to twelve most recently launched unpinned apps from a local history that users can clear; shell-extracted app icons, nested Start-menu folders, and lazy, bounded Documents/Downloads/Music/Pictures/Videos flyouts for files and two levels of folders; Settings, This PC, Control Panel, Network, Recent, and Run shortcuts; Lock, Sleep, Hibernate, Sign out, Restart, and Shut down actions with confirmation for session-ending actions; the Windows 7-inspired header shows the account name and local Windows account picture when available, with initials as fallback; authentic Win7/8 styling remains |
| Taskbar | Classic/replacement taskbar and edge placement | Partial: live overlays on the primary display or all connected displays, with per-display placement, a dedicated Windows Search button, window switching, optional sign-in startup, and an opt-in replacement mode that hides Windows taskbars only on covered displays, monitors for Explorer-created replacements, and restores each captured taskbar visibility state on normal or unexpected app exit; deep Explorer integration and the native Start/taskbar relationship remain |
| Taskbar | Labels, icon size, margins, grouping, drag/drop | Partial: optional window labels, extracted app icons with three icon sizes, compact/standard/relaxed button spacing, centered or left-aligned app buttons while Start stays left, persistent reorderable launch pins with Win+1–9 launch shortcuts and Win+T keyboard taskbar focus when Windows-key integration is enabled, pins absorb one matching running window and expose additional instances as separate buttons when ungrouped (grouped pinned windows remain available through previews), folder pins browse up to 20 visible children per level across two nested folder levels from a lazy context-menu flyout and can open locations in File Explorer, subtle running and accent active-state indicators, current-session reorderable unpinned-window buttons and drag-reorderable DWM preview cards shared across displays, active-window second-click minimize, middle-click close of the foreground window in a group, executable/shortcut/folder drag-and-drop, document-to-app drop, and three bar sizes/grouping preference exist; native taskbar integration remains |
| Taskbar | Segmented/floating/translucent styles and auto-hide | Partial: adjustable 0–70% overlay transparency with an adaptive mode that applies the selected transparency while a maximized app covers a display and returns to a solid surface on the desktop, DWM Desktop Acrylic taskbar backdrop where supported with the existing themed alpha surface retained when unavailable, taskbar accents that follow the current Windows DWM colorization color, optional Aero-style Aura highlights sampled from app-icon colors with a Dynamic Aura spotlight that follows the pointer, edge-aware idle auto-hide with a Win+Alt+T toggle, optional hide when a maximized app covers each display, floating inset style, separate Start/apps/system segments, and an apps-only centered dock capsule that clears the taskbar-wide DWM backdrop around it; native shell integration remains |
| Taskbar | Tray, taskbar context menus, widgets, flyouts, and multi-monitor behavior | Partial: running-window buttons open delayed hover previews with clickable DWM thumbnails, Acrylic-backed host surfaces where supported, and per-window close buttons; grouped minimize/close commands, rounded palette-aware menus with DWM Desktop Acrylic where supported, buttons that open native Widgets, Task View, and the Windows emoji panel, and send Win+D to show the desktop, plus default-output volume/mute controls with output-device selection are available; users can individually show or hide all custom system-area buttons; replacement mode adds a regional-format-aware clock that follows Windows' show-seconds setting, separate Quick Settings and Network buttons (the latter opens Windows' documented Wi-Fi settings URI), keyboard-layout and On-Screen Keyboard buttons using Windows' native Win+Space and Win+Ctrl+O shortcuts, and battery level, charging state, and remaining time when Windows reports a battery, linking to Power settings; button space is measured after visibility changes so app-window capacity adjusts with the selected controls; when the custom bar shares an edge with the native taskbar, the overlay stops at the detected notification-area boundary on bottom, top, left, or right edges so Windows' tray icons, clock, and flyouts remain visible and clickable; device selection uses an undocumented Windows policy COM interface with Sound settings fallback; native shell flyouts remain |
| Taskbar | Per-display and virtual desktop app buttons | Partial: choose to show running app windows on every custom taskbar, only on the display Windows assigns to each window, or on that display and the primary taskbar; spanning windows use Windows' largest-intersection monitor assignment, with geometry fallback for tests and unavailable monitor metadata; pinned launch buttons remain available on every custom taskbar; Windows' documented virtual desktop manager filters running windows to the active desktop by default, with an option to include all desktops and a fail-open fallback when desktop status is unavailable; live physical multi-monitor behavior still needs Windows validation |

| Explorer | Bottom details pane and classic search | Partial: companion Desktop Tuner Explorer has a resizable, hideable two-row bottom details pane showing type, location, size, and modified/created/accessed dates for a selected item, plus common locations, known combined file sizes, and shared or differing dates for multi-selections; recursive current-folder search across names, supported plain-text contents (up to 16 MiB per file), and metadata, with quoted phrases, filename wildcards, extension and file-kind filters, inclusive modified-date bounds, and binary size comparisons; changing native File Explorer's pane placement and search visuals remains |
| Explorer | Folder defaults and legacy view options | Partial: Home/This PC startup, a Home page of recent files that honors Windows' recent-items privacy setting, clickable location breadcrumbs with lazy child-folder dropdown menus, Ctrl+L/Alt+D direct path entry, and Alt+Up parent-folder navigation, file-extension and hidden-item visibility, compact spacing, full-path title bars, separate folder processes, companion Explorer quick-access folders that honor startup/hidden-item/extension preferences and support persistent user-pinned folders by drag-and-drop or context menu with drag reordering, an asynchronous expandable navigation tree for the user folder and available drives that follows the active folder while browsing, respects hidden-item visibility, and skips reparse points, and restoration of open tabs, selected tab, view/sort choices, resizable widths for all six Details columns per folder, navigation/search history, details-pane visibility/height, and the open-folders-in-new-tabs preference between normal launches (explicit folder and This PC launches take precedence), optional per-tab This PC drive grouping by hard disk, removable, optical, network, and other drive type with free-space bars and capacity summaries in all layouts; modern native ribbon/command-bar styling and bottom details-pane placement remain |
| Explorer | Dark mode and common-dialog styling | Partial: companion Start and Explorer windows follow Windows' app light/dark mode live, and the Desktop Tuner settings window, its generated cards, and Explorer title bars follow the Windows app palette and DWM dark-mode frame; settings and Explorer windows request DWM Mica with a solid theme fallback; dark styling for Windows common-dialog contents and Control Panel remains |
| Explorer | Context-menu appearance and behavior | Partial: rounded, live light/dark palette-aware context menus in the companion Start, taskbar, and Explorer surfaces use DWM Desktop Acrylic and small DWM-rounded corners where supported, with a solid themed fallback; touch digitizers trigger 44-DIP menu-item targets with wider padding, while pointer input keeps compact spacing; the per-user classic full-menu switch remains, as does native Windows menu styling |
| Explorer | Open locations from the Windows shell | Partial: optional per-user folder and folder-background commands open filesystem locations in the companion Explorer, forwarding paths to an existing app instance when one is running; Windows 11 may place legacy commands under Show more options, and native Explorer remains the default folder handler |
| Explorer | File rename behavior | Partial: F2 selects a file's name while leaving its final extension unselected; dotfiles and folders remain fully selected for renaming. Native inline rename styling and shell rename integration remain |
| Shell-wide | Classic applet behavior, fonts, colors, and UI consistency | Partial: companion Start and Explorer follow Windows app light/dark mode and accent color, while the custom taskbar and its window previews follow system light/dark mode and accent color live; native Win32 app recoloring, classic applet behavior, and shell-wide font styling remain |
| Reliability | Windows-version compatibility, recovery and resource discipline | Partial: user-level setting snapshots, apply rollback, opt-in per-user sign-in startup, a per-user Windows installer, debounced per-display taskbar reconciliation after Windows display changes, and a shared 200 ms top-level window snapshot that avoids duplicate per-display enumeration exist; builds and regression checks run on the Windows Server 2022 and 2025 hosted images, with package artifacts produced once on 2025; live Windows 10/11 compatibility validation, updater, and telemetry-free resource profiling remain |

The current Windows App SDK and Win32 documentation do not provide public APIs for replacing the system taskbar or arbitrary built-in Start-menu visuals. Reaching behavioral parity in those areas will require compatibility-tested shell integration and a Windows-build test matrix; registry toggles alone do not meet the objective.
